## 简体中文

### 2.5.4：LHDC 自适应策略治理隔离

- 修复实验性 LHDC 链路治理器在「自适应」与「连接优先」播放策略下仍可能发布码率控制目标的问题。这两种策略现在继续收集链路诊断，但不执行码率治理；「音质优先」下的治理行为保持不变。
- 切换播放质量策略时清理旧的学习、限幅、待处理目标与会话控制状态；非「音质优先」期间到达的旧 Native 治理回调不会触发治理动作。
- 补齐 Java 控制器与 Native 侧一致的策略门控，并增加回归测试覆盖观察模式、策略切换、迟到回调及实验开关独立性。

### 升级与边界

- 安装后重新加载官方「无线耳机」及蓝牙作用域。
- 本次修复确认模块侧策略门控已收敛。反馈设备的实际听感仍需升级后复测；现有反馈不足以证明所有卡顿都由码率治理导致，也不代表所有系统和耳机组合均已验收。

## English

### 2.5.4: Isolate LHDC Adaptive mode from bitrate governance

- Fixes an issue where the experimental LHDC link governor could still publish bitrate-control targets in Adaptive and Connection Priority modes. Both modes continue collecting link diagnostics without applying bitrate governance; Quality Priority behavior is unchanged.
- Clears old learning, ceiling, pending-target, and session-control state when the playback-quality policy changes. Late Native governor callbacks received outside Quality Priority do not trigger governance.
- Aligns the Java controller's policy gate with the Native gate and adds regression coverage for observe-only mode, policy changes, late callbacks, and the independent experimental switch.

### Upgrade notes and limits

- Reload the official Wireless Headphones app and Bluetooth scopes after installation.
- This release confirms the module-side policy correction. Playback on the affected headset still needs to be checked after upgrading. The available feedback does not establish that bitrate governance caused every reported stutter or validate every system/headset combination.
